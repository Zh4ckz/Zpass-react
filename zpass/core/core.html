Z Pass & PassGram APIs

We offer three kinds of APIs for developers. The Bot API allows you to easily create programs that use Z Pass messages for an interface. The Z Pass API and Client SDKs allow you to build your own customized Z Pass clients. You are welcome to use both APIs free of charge. Lastly, the Gateway API allows any business, app or website to send verification codes through Z Pass instead of traditional SMS.

Bot API

This API allows you to connect bots to our system. Z Pass Bots are special accounts that do not require an additional phone number to set up. You communicate with this server via a simple HTTPS interface that offers a simplified version of the Z Pass API.

Client SDKs & Libraries

Build third-party applications using official PassGram SDKs:

  • Python SDK: pip install passgram
  • Node.js SDK: npm install passgram
  • PHP SDK: composer require passgram/bot
  • Android Login SDK: PassGram Login Android SDK

MTProto 2.0 Mobile Protocol

Client developers are required to comply with the Security Guidelines.

General Description

The MTProto protocol is designed for high-performance access to Z Pass server API from applications running on mobile and desktop devices. It is subdivided into three independent components:

  • High-level component (API query language): defines how API queries and responses are converted to binary messages.
  • Cryptographic (authorization) layer: defines how messages are encrypted prior to transmission.
  • Transport component: defines how client and server transmit messages over TCP, WebSockets, or HTTPS.

Brief Component Summary

High-Level Component (RPC Query Language/API)

The client and server exchange binary messages inside a session. Each session is attached to a user key ID by which authorization is accomplished.

Authorization and Encryption

Prior to a message being transmitted, it is encrypted using AES-256-IGE. MTProto supports Perfect Forward Secrecy in both cloud chats and secret chats.

Recap

  • Layer 7 (Application): High-level RPC API
  • Layer 6 (Presentation): Type Language (TL)
  • Layer 5 (Session): MTProto session
  • Layer 4 (Transport): TCP / WebSocket / HTTPS
