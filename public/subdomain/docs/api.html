Bot API · v1.0

Bot API reference.

Every method, parameter and object of the PassGram Bot API. Each title has its own link: click # next to it, or open e.g. docs.zpas.org/bot/api#sendMessage. New here? Start with Bots on PassGram.

Introduction#

The Bot API is a plain HTTPS interface. You call a method, PassGram answers with JSON. You can use it from any language, with the official SDK, or with an existing bot library by changing its server address.

Your token#

Every bot has a token from Zbot, for example 8513445453:GQk3yXn2…: the bot's ID, a colon and 43 secret characters. Put it in the address, or in a header.

FormExample
In the address (what libraries use)https://api.zpas.org/bot<TOKEN>/getMe
Headerhttps://botapi.zpas.org/getMe + Authorization: Bearer <TOKEN>
⚠ Keep it secretAnyone with the token controls the bot. If it leaks, send /revoke to Zbot for a new one.

Making requests#

Methods accept GET (query string) and POST with JSON, a URL-encoded form, or multipart/form-data (needed to upload files). In forms, objects such as reply_markup are sent as JSON text. Method names are not case-sensitive. JSON bodies may be up to 64 KB.

curl -X POST https://api.zpas.org/bot$TOKEN/sendMessage \
  -H "Content-Type: application/json" \
  -d '{"chat_id": 45957845239, "text": "Hello!"}'
curl -X POST https://api.zpas.org/bot$TOKEN/sendDocument \
  -F chat_id=45957845239 -F document=@report.pdf -F caption="Report"

Responses#

Every answer is a JSON object. On success ok is true and the data is in result. On failure ok is false, with error_code, a readable description, and sometimes ResponseParameters in parameters.

{"ok": true, "result": {"message_id": 3, "date": 1794200943}}
{"ok": false, "error_code": 400, "description": "Bad Request: chat not found"}
{"ok": false, "error_code": 429, "description": "Too Many Requests: retry after 60",
 "parameters": {"retry_after": 60}}

Errors#

CodeMeaning
400A parameter is wrong or missing. Read description.
401The token is wrong or was replaced.
403The person has not started your bot, or PassGram disabled the bot.
404This method does not exist.
409getUpdates while a webhook is set.
413Upload over 20 MB, or request too large.
429Too many requests: wait retry_after seconds.
5xxTemporary problem: retry after a short pause.

IDs#

Bots have a 10-digit ID; people have an 11-digit Z Pass ID, the same number they see in the app. In a private chat the chat ID equals the person's user ID. chat_id also accepts @username for people who started your bot. message_id counts up within each chat; update_id counts up per bot.

Webhooks#

After setWebhook, each Update is sent to your address as a JSON POST. Answer with any 2xx status. If your server fails, the update waits (up to 24 hours) and is sent again, in order, with the next one. With a secret_token, every delivery has it in the X-ZPass-Bot-Api-Secret-Token header (and in X-Telegram-Bot-Api-Secret-Token, which many libraries check). You may answer with one method call as JSON, e.g. {"method":"sendMessage","chat_id":…,"text":"…"}.

ℹ Polling or webhook?Long polling is easiest while developing. Webhooks are instant and do no work while your bot is idle, so prefer them in production.

Available methods#

Getting updates#

getUpdates#

POST/bot<TOKEN>/getUpdatesLIVE

Returns new updates, oldest first, as an Array of Update. Not available while a webhook is set (409).

ParameterTypeRequiredDescription
offsetIntegerOptionalFirst update to return. Updates before it are confirmed and removed. A negative value returns only the last few.
limitIntegerOptional1–100, default 100.
timeoutIntegerOptionalSeconds to wait when nothing is new (long polling). PassGram waits up to 25.
allowed_updatesArray of StringOptionalmessage, callback_query. Remembered for later calls.

setWebhook#

POST/bot<TOKEN>/setWebhookLIVE

Sends every new update to your HTTPS address as a JSON POST. Returns True. See webhooks.

ParameterTypeRequiredDescription
urlStringYesYour https:// address. Empty removes the webhook.
secret_tokenStringOptional1–256 characters A-Z a-z 0-9 _ -, sent back in a header with every delivery.
allowed_updatesArray of StringOptionalWhich kinds to deliver.
drop_pending_updatesBooleanOptionalForget updates waiting now.

deleteWebhook#

POST/bot<TOKEN>/deleteWebhookLIVE

Removes the webhook so you can use getUpdates. Returns True.

ParameterTypeRequiredDescription
drop_pending_updatesBooleanOptionalForget updates waiting now.

getWebhookInfo#

POST/bot<TOKEN>/getWebhookInfoLIVE

Returns WebhookInfo. No parameters.

No parameters.

Changelog#

What changed in the PassGram Bot API, newest first.

November 9, 2026 · Bot API 1.0#

  • The API now speaks the wire format common bot libraries expect. Tested with python-telegram-bot, aiogram, pyTelegramBotAPI, Telegraf, grammY and node-telegram-bot-api: change the server address and existing bot code works.
  • Numeric IDs: bots get a 10-digit ID (also the first part of new tokens); people are identified by their 11-digit Z Pass ID. Older tokens keep working.
  • New address https://api.zpas.org/bot<TOKEN>/<method>.
  • Webhooks: setWebhook, deleteWebhook, getWebhookInfo, secret header, automatic retries, and answering with a method call.
  • Long polling with timeout in getUpdates; negative offset; confirmed updates are removed.
  • Photos, videos, GIFs, audio, voice, round videos, stickers and files, by link (any size) or upload (up to 20 MB, was 5 MB). Uploads also accept attach://.
  • Formatting with parse_mode (HTML, MarkdownV2, Markdown).
  • Reply keyboards, remove_keyboard and force_reply.
  • editMessageCaption, deleteMessage, deleteMessages, sendChatAction, getChat; edit methods now return the edited message.
  • Bot profile methods: name, description and short description.
  • Messages carry entities for a leading /command, and language_code for the person's app language.
  • Unknown methods return 404 Not Found; method names are not case-sensitive.
  • Official PassGram Bot SDK 1.0 for Python and JavaScript (one file each, no dependencies).
  • Verify Bot: owners can apply for a blue check for their account or bot.

November 2026 · Bot API preview#

  • Inline keyboards, button presses (answerCallbackQuery), editMessageText and editMessageReplyMarkup.
  • sendDocument with a one-time file relay (up to 5 MB).
  • getMe, getUpdates, sendMessage, commands and the menu button.
