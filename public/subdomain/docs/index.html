Bot API · v1 preview

Build bots for PassGram.

A bot is a small program that talks to PassGram users through a simple HTTPS API. You send a request, you receive JSON. This guide shows how to authenticate, read updates, send messages and what is coming next, with copy-ready examples.

⚡ Quick startSend your first message in under five minutes. 📥 Read messagesReceive what users write to your bot. ⌨️ Inline keyboardsButtons under messages, planned for a coming release.

What is live today

This page is honest about the current state of the API so that you never build on something that is not there yet.

FeatureStatusNotes

getUpdatesLIVEPoll for new messages, with offset and limit.
sendMessageLIVEPlain text only, up to 4096 characters.
getMyCommands, setMyCommands, deleteMyCommandsLIVEThe / command list users see in the chat.

Quick start

  1. Create a bot in the PassGram app. You receive a username and a private token.
  2. Ask a user to open your bot and press Start. A bot can only write to people who have started it.
  3. Call the API with your token, as shown below.
# 1. Check the token
curl https://botapi.zpas.org/getMe \
  -H "Authorization: Bearer $TOKEN"

# 2. Send a message
curl -X POST https://botapi.zpas.org/sendMessage \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"chat_id":"USER_ID","text":"Hello from my bot!"}'
const TOKEN = process.env.PASSGRAM_TOKEN;
const api = (method, body) => fetch(`https://botapi.zpas.org/${method}`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${TOKEN}`, 'Content-Type': 'application/json' },
  body: JSON.stringify(body || {})
}).then(r => r.json());

const me = await api('getMe');
await api('sendMessage', { chat_id: 'USER_ID', text: 'Hello from my bot!' });
import os, requests

TOKEN = os.environ["PASSGRAM_TOKEN"]
BASE = "https://botapi.zpas.org"
HEAD = {"Authorization": f"Bearer {TOKEN}"}

print(requests.get(f"{BASE}/getMe", headers=HEAD).json())
requests.post(f"{BASE}/sendMessage", headers=HEAD,
              json={"chat_id": "USER_ID", "text": "Hello from my bot!"})
ℹ NoteBase address: https://botapi.zpas.org. It runs on Cloudflare, close to your users. The same API is also reachable at https://zpass-zbot.rezanhassoun.workers.dev.

Authentication

Every request needs your bot token. It looks like 24 hex characters : 43 characters. Whoever has the token controls the bot, so treat it like a password.

MethodHowRecommended
HeaderAuthorization: Bearer <TOKEN>YES
URL path/bot<TOKEN>/getMeNo. Tokens in URLs can end up in access logs.
⚠ Neverput a token in a web page, a mobile app bundle or a public repository. If it leaks, rotate it immediately in the app.

GET and POST

Methods accept GET (parameters in the query string) or POST (JSON body). Use POST for anything that changes data, such as sendMessage, and GET for simple reads like getMe.

GEThttps://botapi.zpas.org/getUpdates?offset=0&limit=20
POSThttps://botapi.zpas.org/sendMessage

Other HTTP methods return 405. Send Content-Type: application/json with POST bodies.

Responses

Every answer is JSON with an ok flag.

{
  "ok": true,
  "result": { /* method specific */ }
}
{
  "ok": false,
  "error_code": 401,
  "description": "Invalid token"
}

Errors

CodeMeaningWhat to do
400Bad request: invalid chat, empty text, text over 4096 characters, bad offset/limit, or an unsupported field such as reply_markup.Fix the parameters.
401Invalid token.Check or rotate the token.
403The user has not started your bot, or the bot was disabled by Z Pass.Ask the user to press Start. If the bot is disabled, contact support.
405Only GET and POST are allowed.Change the HTTP method.
429Too many requests.Wait one minute and retry.
501Method not implemented yet.See the planned features below.
500Server error.Retry with a short delay.

Rate limits

Each bot can make up to 120 requests per minute. Above that you receive 429 until the minute ends. Fetch updates in batches of up to 100, send only what is useful, and back off when you see a 429.

Returns basic information about your bot. Use it to confirm the token is valid.

{ "ok": true,
  "result": { "id": "a1b2c3...", "is_bot": true,
              "first_name": "My Bot", "username": "my_bot" } }

getUpdates

GETPOST/getUpdatesLIVE

Returns new messages and events that users sent to your bot, oldest first. Updates are kept for a limited time, so fetch them regularly.

ParameterTypeDescription
offsetintegerReturn updates with update_id greater than or equal to this value. Use the last update_id + 1 to move past what you processed. Default 0.
limitinteger1 to 100. Default 100.
curl "https://botapi.zpas.org/getUpdates?offset=0&limit=20" \
  -H "Authorization: Bearer $TOKEN"
const r = await fetch('https://botapi.zpas.org/getUpdates?offset=0&limit=20',
  { headers: { Authorization: `Bearer ${TOKEN}` } }).then(r => r.json());
for (const u of r.result) console.log(u.update_id, u.message?.text);
r = requests.get(f"{BASE}/getUpdates", params={"offset": 0, "limit": 20}, headers=HEAD).json()
for u in r["result"]:
    print(u["update_id"], u.get("message", {}).get("text"))

Update object

FieldDescription
update_idIncreasing number. Use update_id + 1 as your next offset.
messageThe message, with text, chat.id and message_id. Fields can grow over time, so ignore ones you do not know.

Commands

POST/setMyCommandsLIVE
GETPOST/getMyCommandsLIVE
POST/deleteMyCommandsLIVE

Commands appear when a user types / in the chat with your bot. You can also manage them without code in the app: open Zbot and choose your bot.

FieldRules
command1 to 32 characters: lowercase letters, digits and _, starting with a letter. A leading / is removed.
description1 to 100 characters.
ListUp to 100 commands, no duplicates. setMyCommands replaces the whole list.
curl -X POST https://botapi.zpas.org/setMyCommands \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"commands":[{"command":"start","description":"Start the bot"},{"command":"help","description":"How it works"}]}'
await api('setMyCommands', { commands: [
  { command: 'start', description: 'Start the bot' },
  { command: 'help', description: 'How it works' },
] });
const { result } = await api('getMyCommands');
{ "ok": true, "result": [ { "command": "start", "description": "Start the bot" } ] }

Menu button & mini apps

POST/setChatMenuButtonLIVE
GETPOST/getChatMenuButtonLIVE

The menu button sits next to the message box. It can open the command list, open a mini app (a web page shown inside the chat), or be hidden.

menu_button.typeExtra fieldsResult
commandsnoneOpens the / command list. Default.
web_apptext (1 to 32 characters), web_app.url (https only)Opens your mini app.
defaultnoneNo menu button.
curl -X POST https://botapi.zpas.org/setChatMenuButton \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"menu_button":{"type":"web_app","text":"Open store","web_app":{"url":"https://shop.example.com/app"}}}'
curl -X POST https://botapi.zpas.org/setChatMenuButton \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"menu_button":{"type":"commands"}}'
ℹ Mini appsThe page opens in a secure in-app browser. Use HTTPS, design for phone screens, and never ask users for their PassGram password or codes inside a mini app.

Send documents PLANNED

A sendDocument method will let your bot send files such as PDFs and reports, up to a size limit, with an optional caption.

curl -X POST https://botapi.zpas.org/sendDocument \
  -H "Authorization: Bearer $TOKEN" \
  -F chat_id=USER_ID -F document=@report.pdf -F caption="Monthly report"

Until it ships, calling it returns 501 Method not implemented.

Get user PLANNED

For privacy, bots will see only what a user has chosen to share with them: a chat id, a display name and a username. A getChat style method is planned to read that information for users who started your bot. Bots will never see passwords, keys or private vault content.

Webhooks PLANNED

Today you fetch updates with getUpdates. Webhooks will let PassGram call your HTTPS server when something happens. When they arrive, verify the signature on every request, accept only HTTPS and answer within a few seconds.

Example: echo bot

A complete bot that repeats every message back. It reads updates, remembers the last id, and replies.

const TOKEN = process.env.PASSGRAM_TOKEN, BASE = 'https://botapi.zpas.org';
const call = (m, body) => fetch(`${BASE}/${m}`, { method: 'POST',
  headers: { Authorization: `Bearer ${TOKEN}`, 'Content-Type': 'application/json' },
  body: JSON.stringify(body || {}) }).then(r => r.json());

let offset = 0;
while (true) {
  const { ok, result } = await call('getUpdates', { offset, limit: 50 });
  if (ok) for (const u of result) {
    offset = u.update_id + 1;
    const m = u.message;
    if (m?.text) await call('sendMessage', { chat_id: m.chat.id, text: `You said: ${m.text}` });
  }
  await new Promise(r => setTimeout(r, 2000)); // stay under 120 requests/min
}
import os, time, requests
TOKEN, BASE = os.environ["PASSGRAM_TOKEN"], "https://botapi.zpas.org"
H = {"Authorization": f"Bearer {TOKEN}"}
offset = 0
while True:
    r = requests.post(f"{BASE}/getUpdates", headers=H, json={"offset": offset, "limit": 50}).json()
    for u in r.get("result", []):
        offset = u["update_id"] + 1
        m = u.get("message")
        if m and m.get("text"):
            requests.post(f"{BASE}/sendMessage", headers=H, json={"chat_id": m["chat"]["id"], "text": "You said: " + m["text"]})
    time.sleep(2)

Security best practices

  • Keep the token on a server, in an environment variable or secret manager.
  • Send it in the Authorization header, not in the URL.
  • Rotate it right away if it may have leaked.
  • Never ask users for passwords, recovery keys or one-time codes. PassGram never does either.
  • Treat everything users send as untrusted input. Validate and escape it before using it.
  • Handle 429 and 5xx with a delay, not a tight retry loop.

MTProto 2.0 protocol

MTProto 2.0 provides high-speed binary serialization over TCP and HTTPS with Diffie-Hellman key exchange and AES-256-IGE payload encryption.

// DH key exchange & encrypted frame structure
auth_key_id:int64 msg_key:int128 encrypted_data:bytes

Type Language (TL) schema

Z Pass schemas are defined in Type Language syntax:

user#2e2e12a id:long first_name:string username:string = User;
message#8d8d21c id:long sender_id:long text:string date:int = Message;

End-to-end encryption

Private chats are end-to-end encrypted and stay that way. Bot conversations are different: they are readable by the bot operator and by the Z Pass server, because the bot program has to read them to answer. Never send passwords, recovery keys or payment secrets to a bot.
