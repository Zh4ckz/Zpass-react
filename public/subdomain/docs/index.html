Bot API · v1

Build bots for PassGram.

A bot is a program that chats with PassGram users over a plain HTTPS API: you call a method, you get JSON back. The wire format follows the conventions most bot libraries already speak, so you can point an existing Python, JavaScript or PHP library at PassGram by changing one address.

📚 Full referenceEvery method, field and type, each with its own # link. 🧩 Use your librarypython-telegram-bot, aiogram, Telegraf, grammY and more, tested. ⚡ WebhooksUpdates pushed to your server the moment they happen. 🖼 Photos & filesSend links from your own server, or small uploads.

What is live today

Everything in this table works now. Anything else returns 404 Not Found, so you never build on something that is not there.

ReceivegetUpdates (with long polling), setWebhook, deleteWebhook, getWebhookInfo
SendsendMessage, sendPhoto, sendVideo, sendAnimation, sendAudio, sendVoice, sendVideoNote, sendSticker, sendDocument, sendChatAction
ButtonsInline buttons, reply keyboards, remove_keyboard, force_reply, answerCallbackQuery
ChangeeditMessageText, editMessageCaption, editMessageReplyMarkup, deleteMessage, deleteMessages
Formattingparse_mode: HTML, MarkdownV2, Markdown

Bots talk to people in private chats. Groups, channels, inline mode and payments are not available to bots yet.

Quick start

  1. Create a bot in the PassGram app: open Zbot and send /newbot. You get a username and a private token.
  2. Open your bot in PassGram and press Start. A bot can only write to people who started it.
  3. Call the API with your token.
# Who am I?
curl https://api.zpas.org/bot$TOKEN/getMe

# Read what people sent (waits up to 25 s for something new)
curl "https://api.zpas.org/bot$TOKEN/getUpdates?timeout=25"

# Answer, using chat.id from an update
curl -X POST https://api.zpas.org/bot$TOKEN/sendMessage \
  -H "Content-Type: application/json" \
  -d '{"chat_id":45957845239,"text":"Hello from my bot!"}'
const API = `https://api.zpas.org/bot${process.env.PASSGRAM_TOKEN}`;
const call = (method, body = {}) => fetch(`${API}/${method}`, {
  method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body),
}).then((r) => r.json());

console.log(await call('getMe'));
await call('sendMessage', { chat_id: 45957845239, text: 'Hello from my bot!' });
import os, requests

API = f"https://api.zpas.org/bot{os.environ['PASSGRAM_TOKEN']}"
print(requests.get(f"{API}/getMe").json())
requests.post(f"{API}/sendMessage", json={"chat_id": 45957845239, "text": "Hello from my bot!"})

Tokens & addresses

A token looks like 8513445453:GQk3yXn2…: your bot's number, a colon, then 43 secret characters. Whoever has it controls the bot, so treat it like a password. PassGram stores only a hash of it; if you lose it, make a new one with /revoke in Zbot.

AddressUse
https://api.zpas.org/bot<TOKEN>/<method>The standard form. This is what libraries use.
https://botapi.zpas.org/<method> + header Authorization: Bearer <TOKEN>Same API with the token kept out of the URL. Handy for your own HTTP code.

Method names are not case-sensitive. Tokens made before numeric IDs existed (24 hex characters before the colon) keep working; /revoke gives you a token in the new form.

IDs

IDLooks likeNotes
Bot ID10 digits, for example 8513445453The number before the colon in the token, also in getMe.
User / chat ID11 digits, for example 45957845239The person's Z Pass Cloud ID, the same number they see in the app. In a private chat, chat.id and from.id are equal.
message_id1, 2, 3…Counts up within each chat.
update_id1, 2, 3…Counts up per bot.

chat_id also accepts a person's @username, as long as they have started your bot.

Sending requests

Use GET with query parameters, or POST with a JSON body, a URL-encoded form, or multipart/form-data (needed for file uploads). In forms, send objects such as reply_markup as JSON text. JSON bodies can be up to 64 KB; uploads up to 20 MB.

Responses

Every answer is JSON with an ok flag. Successful calls carry result; failures carry error_code and a readable description.

{ "ok": true, "result": { /* depends on the method */ } }
{ "ok": false, "error_code": 400, "description": "Bad Request: chat not found" }
{ "ok": false, "error_code": 429, "description": "Too Many Requests: retry after 60",
  "parameters": { "retry_after": 60 } }

Errors

CodeMeaningWhat to do
400Something in the request is wrong: unknown chat, empty or too long text, bad button, unsupported value.Read description and fix the parameters.
401The token is wrong or was replaced.Check the token, or make a new one.
403The person has not started your bot, or PassGram disabled the bot.Ask them to press Start. For a disabled bot, contact support.
404The method does not exist here.Check what is live.
409getUpdates was called while a webhook is set.Use one or the other; deleteWebhook switches back to polling.
413Upload over 20 MB.Send an https link instead.
429Too many requests.Wait retry_after seconds.
5xxTemporary server problem.Retry after a short delay.

getUpdates

GETPOST/getUpdatesLIVE

Returns what happened since you last asked, oldest first. Pass offset = last update_id + 1 to confirm what you handled; confirmed updates are removed.

ParameterTypeDescription
offsetintegerFirst update to return. A negative value returns only the last few updates.
limitinteger1–100, default 100.
timeoutintegerSeconds to wait when nothing is waiting (long polling). PassGram holds the request up to 25 seconds.
allowed_updatesarrayKinds you want, for example ["message","callback_query"]. Remembered for later calls.
ℹ TipLong polling is fine for development. For a bot in production, webhooks are faster and do no work while your bot is idle.

Webhooks LIVE

With a webhook, PassGram sends each update to your HTTPS address as a JSON POST, right when it happens. Answer with any 2xx status to confirm it. If your server is down or answers with an error, the update waits and is sent again, in order, together with the next one (for up to 24 hours).

MethodParameters
setWebhookurl (https), optional secret_token (1–256 of A–Z a–z 0–9 _ -), allowed_updates, drop_pending_updates. An empty url removes the webhook.
deleteWebhookoptional drop_pending_updates
getWebhookInfoReturns url, pending_update_count and the last delivery error, if any.

When you set a secret_token, every delivery carries it in the X-ZPass-Bot-Api-Secret-Token header, and also in X-Telegram-Bot-Api-Secret-Token, the header name many libraries check. Reject requests where it does not match.

Your answer can also be one method call: reply with JSON such as {"method":"sendMessage","chat_id":…,"text":"…"} and PassGram runs it, which saves a request.

curl -X POST https://api.zpas.org/bot$TOKEN/setWebhook \
  -H "Content-Type: application/json" \
  -d '{"url":"https://bot.example.com/passgram","secret_token":"long-random-string"}'
const http = require('node:http');
http.createServer(async (req, res) => {
  if (req.headers['x-zpass-bot-api-secret-token'] !== process.env.HOOK_SECRET) { res.writeHead(401).end(); return; }
  let body = ''; for await (const c of req) body += c;
  const update = JSON.parse(body);
  const m = update.message;
  res.writeHead(200, { 'Content-Type': 'application/json' });
  res.end(m ? JSON.stringify({ method: 'sendMessage', chat_id: m.chat.id, text: `You said: ${m.text}` }) : '{}');
}).listen(8080);

Buttons that sit under a message. reply_markup.inline_keyboard is a list of rows; each row is a list of buttons. One button per row makes a list; two make a grid. Buttons in a row share the width.

Button presses

A press on a callback_data button arrives as a callback_query update with id, from, message (the message the button belongs to), chat_instance and data. The button spins until you call answerCallbackQuery; do it within 10 seconds. Its optional text (up to 200 characters) shows as a short notice in the app.

cq = update.get("callback_query")
if cq:
    call("answerCallbackQuery", callback_query_id=cq["id"], text="Done ✅")
    call("editMessageText", chat_id=cq["message"]["chat"]["id"],
         message_id=cq["message"]["message_id"], text="You picked " + cq["data"])

Reply keyboards

A reply keyboard shows big answer buttons above the message box. A tap sends the button's text as a normal message from the person, so you handle it like any other text.

FieldDescription

one_time_keyboardHide the keyboard after the person answers.
resize_keyboard, is_persistent, input_field_placeholderAccepted.

Send {"remove_keyboard": true} to take it away.

Example bot

A complete echo bot with plain HTTP and long polling, no library needed.

const API = `https://api.zpas.org/bot${process.env.PASSGRAM_TOKEN}`;
const call = (m, body = {}) => fetch(`${API}/${m}`, { method: 'POST',
  headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body) }).then((r) => r.json());

let offset = 0;
for (;;) {
  const { ok, result } = await call('getUpdates', { offset, timeout: 25 });
  if (!ok) { await new Promise((r) => setTimeout(r, 5000)); continue; }
  for (const u of result) {
    offset = u.update_id + 1;
    const m = u.message;
    if (m?.text) await call('sendMessage', { chat_id: m.chat.id, text: `You said: ${m.text}` });
  }
}
import os, time, requests
API = f"https://api.zpas.org/bot{os.environ['PASSGRAM_TOKEN']}"
offset = 0
while True:
    r = requests.post(f"{API}/getUpdates", json={"offset": offset, "timeout": 25}, timeout=40).json()
    if not r.get("ok"):
        time.sleep(5); continue
    for u in r["result"]:
        offset = u["update_id"] + 1
        m = u.get("message")
        if m and m.get("text"):
            requests.post(f"{API}/sendMessage", json={"chat_id": m["chat"]["id"], "text": "You said: " + m["text"]})

Not supported (yet)

  • Groups and channels: bots chat with people one to one.
  • Inline mode, games, payments and sticker sets.
  • Receiving files from people (getFile), forwarding and copying messages.
  • Reusing a file_id (see Photos & files).

Calling one of these returns 404 Not Found.

Security

  • Keep the token on your server, in an environment variable or a secret manager. Never ship it in an app or a web page.
  • Make a new token at once if it may have leaked.
  • Use a secret_token with webhooks and check it on every request.
  • Never ask people for passwords, recovery keys or one-time codes. PassGram never does.
  • Treat everything people send as untrusted input.
  • On 429 or 5xx, wait before retrying.

Privacy

Private chats between people are end-to-end encrypted and bots cannot see them. Chats with a bot are different: the bot's operator reads them (the bot has to, to answer) and they pass through the PassGram server. The app tells people this in the bot chat. Bots never see phone numbers, email addresses, passwords or vault content.

PassGram can disable or remove bots that break the Terms, for example after reports from users.
