Guide

Understand the API
before you build.

This page explains how PassGram bots are expected to work, how to keep them secure, and which parts exist today. We mark every planned feature as planned, so you can decide what to build on without surprises.

1

Authentication

Every bot receives a secret token when it is created. The token is part of the request path and identifies your bot. Treat it exactly like a password: store it in an environment variable or a secrets manager, never inside a web page, mobile app or public repository.

If a token leaks, revoke it and issue a new one immediately. Rotating a token invalidates the old one at once.

2

Requests and responses

Methods are called with HTTPS POST and a JSON body. Successful calls return a JSON object with an ok flag and a result, while failures return ok set to false together with an error code and a short human-readable description.

3

Rate limits

To keep the service fast for everyone, bots will be limited in how many messages they can send per second and per chat. When a limit is reached the response tells you how many seconds to wait, and well-behaved clients should back off instead of retrying immediately.

4

Webhooks and polling

You will be able to receive updates either by asking for them on a schedule or by giving us an HTTPS address to call. Webhooks are faster and use fewer resources, while polling is easier to test from a laptop.

Best practice

Ship it safely.

Always call the API from a server you control. Browsers expose every line of script to the person using the page, so any token placed there can be copied in seconds. A small backend that holds the token and exposes only the actions your page needs is the safest pattern.

Validate everything that reaches your bot. Messages and webhook payloads are input from the outside world, so check their shape, limit their length and never run them as commands. Log failures without writing tokens into your logs.

Finally, be transparent with the people who talk to your bot. Say what it does, what it stores and how they can stop using it. Trust is the most valuable feature any integration can have.
